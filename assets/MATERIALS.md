# Biological materials

RGB is only one part of a vertex material. The mesh also stores roughness, index of refraction (IOR), and subsurface scattering data. The ray shader interpolates these values across each triangle. Roughness controls direct-light highlight width: low values give a narrow highlight; high values spread it. It does not change the mesh outline. Surface detail that changes an outline still needs geometry.

`models/source/biology_materials.json` defines 17 surface profiles. Its local schema is `schemas/biology-materials.schema.json`. Each profile has `roughness_min`, `roughness_max`, `ior`, `frequency`, `pigment_low`, `pigment_high`, and `subsurface`. The subsurface object has a `weight` in `[0,1]` and three positive `radius` values in local mesh units. These RGB distances control absorption of transmitted light. Pigment values are RGB multipliers in `[0,1]`. The generator bakes broad object-space variation into vertex RGB and roughness. It rejects duplicate fields, unknown surfaces, missing fields, non-finite numbers, and invalid ranges. `roughness_min` must not exceed `roughness_max`.

Edit the profiles, run `scripts/make_biology.py` in Blender, rebuild the asset bundle, and restart the application. This requires no material image maps and adds no render-time noise. The membrane, nucleus, vesicles, internal fibres, capsids, sheaths, immune tissue, granules, fungal stalks, caps, and spikes have separate finishes. The backdrop keeps its earlier material. `--scene-state` reports roughness, IOR, scattering weight, and scattering distance ranges for each loaded mesh. Ambient reflection remains an analytic gradient approximation; roughness controls the studio-light highlights.

Runtime meshes use little-endian `FLMESH02`: eight-byte magic, two uint32 counts, sixteen floats per vertex, and four uint32 values per triangle. Vertex fields are position XYZ, IOR, normal XYZ, emission, linear RGB, roughness, scattering distance RGB, and scattering weight. The loader also accepts `FLMESH01`, which has twelve floats per vertex and zero scattering. Triangle fields are three indices and a surface tag: 0 dielectric, 2 conductor, 3 thin transmission. Tag 1 is unsupported. The loader checks length, indices, finite values, normals, materials, and area. Invalid scattering data fails startup even when SSS is disabled.

The render file's `subsurface` object controls `strength`, `wrap`, `transmission`, `membrane_thickness`, and `samples_per_pixel`. The first three values are in `[0,1]`. Wall thickness is in `(0,1]` world units. The sample budget must be positive and cannot exceed the film sample count. The default uses one existing film sample for thickness transport. An odd budget uses the center film sample when one exists; other selected samples use mirrored pairs. Diffuse softening uses every film sample. No extra camera sample is added. The 256-film reference uses all 256 samples for SSS.

SSS softens diffuse lighting and adds colored backlighting through the strongest back light. It traces solid thickness against the same current instance and then checks light visibility from the entry side. A missing exit contributes no transmitted light. Thin membranes use authored wall thickness instead of cell diameter. Loading scales scattering distance with the mesh; shading applies the smallest instance-axis scale. Specular highlights and clear wall transmission keep their separate responses. Conductors and the decorative backdrop do not scatter. This is an approximation, with no random walk or spatial diffusion solve.

The solid exit search stops after eight times the largest scattering distance. The approximation follows the wrap-lighting and thickness-attenuation methods in [GPU Gems 16](https://developer.nvidia.com/gpugems/gpugems/part-iii-materials/chapter-16-real-time-approximations-subsurface-scattering).
